# Smart Merge Images 使用说明

把 AI 改过的局部图片，按正确位置、正确大小放回原图，并把接缝和色差处理干净。
输入可以是单张，也可以是多块（每块尺寸可以不一样），一次执行输出一张合并图。

![node] 类别：`Element_easy/image`，输出：`Merged_Image`（IMAGE）

---

## 一、最少怎么接

```
原图 ─────────────► original_image
AI 编辑后的块 ─────► edited_crop_B
编辑前裁块(可选) ──► original_crop_A     ← 强烈建议接，最稳
ElementTileSplit 的 grid(可选) ► split_grid  ← 用 TileSplit 拆分时就接上
```

- **接 `original_crop_A`**：节点知道每块原本在画面的哪里，对位最准，还能自动修局部变形。
- **接 `split_grid`**：贴图边缘的渐变/圆角与 TileSplit 完全一致，多块拼接不会有硬边。
- 都不接也能用：节点会在背景上自动找位置，但复杂画面偶尔会贴歪，此时对位失败的分块会被**跳过**（保留原图，不会硬贴到画面中间）。

**推荐的初始参数**

| 参数 | 建议 |
|---|---|
| 形变校正 `warp_method` | 开 |
| 光流模式 `optical_flow` | 开（慢一点） / 关（快） |
| TPS `use_tps` | 开 |
| 色彩 `color_match` | `Patch_based_color` 或 `Edge_Weighted_Color` |
| 羽化 `feather_kernel` | 20~40（拼接缝明显时加到 40~60） |
| `use_gpu` | 开 |

---

## 二、每个参数对结果的影响

### 1. 形变校正 `warp_method`（默认关）
决定"贴图时要不要修 AI 重绘造成的局部变形"。

- **关**：只做整体定位，纯几何，最快最稳。
- **开**：在定位基础上继续修细节错位（表情、衣褶、边缘轻微变形）。

> 影响：开 → 贴合度更好，代价是变慢；画面没有局部变形时可以关。

### 2. 光流模式 `optical_flow`（默认关，仅 `warp_method` 开时生效）
- **关 = Farneback**：CPU 算法，最快。
- **开 = DIS**：质量更好，边缘更干净，推荐。

> 影响：只影响"精修"的精度和速度，不影响力矩/位置。切换它不会触发重新对齐。

### 3. 非刚性校正 `use_tps`（默认开）
- **开**：允许轻度弯曲/拉伸去贴合背景，AI 重绘常见的"内容对了但形状差一点"靠它修。
- **关**：只做整体平移缩放旋转，最快。

> 影响：开 → 局部变形能修好；关 → 变形会被直直贴回去。

### 4. 精修平滑 `warp_smooth`（默认 1.0，0~4）
只在最后一步"整图精修"里起作用，控制修正位移的平滑程度。

- **调大**：修正更平缓、更保守，几乎不会产生局部扭动。
- **调小 / 0**：允许更细碎的位移修正，可能更贴合，也更容易出现轻微抖动。

> 注意：当每个分块对齐误差已经很小（<0.8px）时，节点会自动跳过整图精修，这个参数就不起作用了。

### 5. 色彩策略 `color_match`（默认 `Patch_based_color`）
这是对成品观感影响最大的参数。**六种模式是从"会改色"到"不改色"的渐变**：

| 模式 | 作用 | 适合 | 注意 |
|---|---|---|---|
| `Patch_based_color` | 分块校正色差，逐区域对齐背景色调；AI 编辑区有减弱保护 | 色差大、不均匀（一半偏暖一半偏冷）；多块拼接 | 最慢；编辑内容不会被拉回背景色，但仍会施加少量校正 |
| `Edge_Weighted_Color` | 用边缘未改动区域统一色调 | 整体偏色，同时要**保住 AI 改的颜色**（如把衣服改成红色） | 全局一个方向校正，局部多色差处理不如 Patch |
| `LAB_Mean` | 整块按均值/方差对齐到背景 | 色差单一、想快速出图 | 内容大改的区域可能被整体冲淡 |
| `Laplacian Pyramid Blend` | 多频段融合，只解决接缝 | 颜色本来就对，只是接缝难看 | **不做色彩校正** |
| `SeamlessClone (PS Auto Blend)` | 泊松融合 | 内容基本没变，只想去接缝 | **内容大改区域会褪色/发灰，慎用** |
| `Alpha Soft Blend` | 仅羽化混合 | 几乎没色差，最快 | 有色差时完全不处理 |

> 实用结论：
> - 出现**灰块/颜色被冲淡** → 换 `Edge_Weighted_Color`，或别用 SeamlessClone。
> - 只要接缝好看、颜色已经对 → `Laplacian Pyramid Blend`。
> - 想要最快看构图 → `Alpha Soft Blend`。

### 6. 羽化 `feather_kernel`（默认 20，0~256）
贴图边缘的柔和过渡宽度，也决定色彩校正的"分块大小"。

- **调大**：接缝更柔、更隐形；色彩过渡更平滑。但会吃进更多原图内容，细节可能被软化，也更慢。
- **调小**：边缘更利落，保留更多原始细节；太小会在接缝处看出边界或色彩台阶。
- **0**：硬边贴图，仅用于不需要融合的场合。

> 经验：普通重绘 20~30；多块拼接/大图 40~60；TileSplit 流程一般跟它的 overlap 配套。

### 7. 合并方式 `merge_mode`（默认 All to One）
- **All to One**：所有编辑块按顺序贴回**第一张**背景，输出 1 张（多元素拼贴）。
- **One to One**：背景与编辑块一一配对，输出数量与背景相同（批量处理多张图）。

### 8. `use_gpu`（默认开）
用显卡加速匹配/光流。显存不足或没有 CUDA 时关掉，功能一样，只是慢。

### 9. `force_recompute`（默认关）
节点会缓存上一次的对齐结果（最多 4 组）。同输入再跑时：

- 改**色彩模式、羽化、光流模式、平滑**等不影响位置的参数 → **不会重新对齐**，几秒出图。
- 勾上 `force_recompute` → 强制清缓存、从头对齐（想对比不同对齐结果时用）。

## 三、常见问题速查

| 现象 | 处理 |
|---|---|
| 有灰块 / AI 改的颜色被拉淡 | 别用 `SeamlessClone`；改用 `Edge_Weighted_Color` |
| 接缝看得见 | 羽化加大到 30~50；或改用 `Laplacian Pyramid Blend` |
| 分块贴歪或缺失 | 接 `original_crop_A`；用 TileSplit 时接 `split_grid`；日志会提示哪块被跳过 |
| 局部变形没修好 | `use_tps` 开 + `warp_method` 开 |
| 拼接处有横竖条纹/错位 | 检查 `split_grid` 是否来自同一次拆分 |
| 太慢 | `optical_flow` 关；色彩换轻量模式；不要频繁勾 `force_recompute` |
| 改色物体被"纠正"回原色 | 用 `Patch_based_color` 或 `Edge_Weighted_Color`，避开 `LAB_Mean`/`SeamlessClone` |

## 四、输入输出说明

- 三个图像端口都支持**单张 / 批量 / 列表**，不需要额外的 "Image List To Image Batch" 节点。
- 每块编辑图可以尺寸不同，节点按各自原始分辨率处理。
- `original_crop_A` 数量/尺寸与 B 不必严格一致，按顺序配对。
- 输出：`All to One` 为 1 张；`One to One` 为与背景数量相同的 batch。
- 无法可靠定位的分块会被跳过并在日志中列出，对应区域保留原图内容。
